# Contributing

## Repository map

| Path | What it is |
| --- | --- |
| `services/execution-service/` | Spring Boot; authoritative trading, owns `execution_db` |
| `services/market-data-service/` | Spring Boot; rebuildable public projections, owns `market_data_db` |
| `event-contracts/` | Avro schemas and `WireEvents`; `--release 17`; wire types only |
| `analytics-job/` | Flink job; `--release 17`, tests on JDK 17, no Boot dependency graph |
| `web/` | React/TypeScript SPA and the nginx reverse proxy config |
| `simulator/` | Python bots, managed by uv |
| `infra/` | Database init script, Kafka topics, Prometheus, Grafana |
| `scripts/` | `init-env`, `compat-gate` (`.ps1` and `.sh`) |
| `docs/` | Dependency baseline, milestones, architecture decisions |

## Rules that are easy to break

- Risk, matching and settlement commit in **one** Execution database transaction. Never split them across services, datasources or transactions.
- Each service touches only its own database. Flyway runs as `*_owner`; the runtime uses `*_app`, which has no DDL. New tables need explicit `GRANT`s in their migration.
- Kafka is downstream of commit and never a startup or readiness dependency of either service.
- Flink never loads Java 25 classes or Boot. Decode and encode events through `WireEvents`: Avro 1.12.2 rejects untrusted classes, and a new event type must be added to its trust list.
- Money is `long` cents with checked arithmetic, never `double`.
- No floating image tags, version ranges or snapshot dependencies. Record baseline changes and rerun the gate.

## Workflow

- Never commit directly to `main`. Use one branch per task, named `<type>/<topic>`, such as `feat/order-book`.
- Write small commits in Conventional Commits form, such as `feat(trading): add price-time book`. Each commit builds, and tests go in with the code they cover.
- Keep PRs reviewable: aim for under about 400 changed lines, excluding lockfiles and generated files.
- Branches may be stacked, with the PR base set to the branch below. A PR merges into its base, so its base must be `main` when it is merged. The repository deletes merged branches, which retargets the next PR automatically.
- Use merge commits. Squash and rebase merging are turned off because they break stacked branches.
- CI must be green before merging, and a PR states what was run and what was not.

After cloning: `git config core.hooksPath .githooks`.

## Commands (Windows PowerShell, from the repository root)

Set these once per shell. `JAVA_HOME` must be Oracle JDK 25.0.5, and `JAVA17_HOME` any JDK 17:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-25.0.5.0.3'
$env:JAVA17_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-17.0.20.101-hotspot'
```

```powershell
.\mvnw.cmd -B -ntp test                                        # Docker-free unit tests
.\mvnw.cmd -B -ntp verify                                      # plus Testcontainers *IT tests (needs Docker)
.\mvnw.cmd -B -ntp -pl services/execution-service -am verify   # one service; same for market-data-service, analytics-job
.\scripts\compat-gate.ps1                                      # full compatibility gate in a throwaway project
```

```powershell
.\scripts\init-env.ps1                                         # first run: creates .env with random secrets
docker compose up -d --build --wait                            # base stack on http://localhost:8080
docker compose --profile full up -d --build --wait             # plus Flink and the simulator
docker compose --profile observability up -d --wait            # plus Prometheus and Grafana
docker compose down                                            # stop; volumes keep the data
```

```powershell
cd web; npm ci; npm run typecheck; npm run lint; npm test; npm run build; cd ..
cd simulator; uv sync --frozen; uv run --frozen ruff check .; uv run --frozen pytest -q; cd ..
```

## Conventions

- Test names: `*Test` is Docker-free (Surefire); `*IT` needs Docker (Failsafe); `*Smoke` runs only from the gate against a live stack.
- Service tests use the real init script and roles through `TestcontainersConfiguration`; there is no H2.
- Spring code uses tabs, as generated by Initializr. Comments explain why, and only where it is not obvious.
- On Windows, stage scripts with the executable bit: `git add --chmod=+x <script>`.
